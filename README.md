# 🤖 工具调用 Agent

一个能**自己决定用什么工具、用几步**的 Agent。不是「问一句答一句」的聊天机器人。

> 核心区别：
> 聊天机器人只会**说**；Agent 会**做**——算数、查时间、翻私有知识库、读本地文件。
> 而且它**不是按你写死的流程走的**，是先看一眼问题，自己决定第一步干什么，
> 拿到结果再决定下一步，直到能回答为止。

---

## 一、它长什么样

跑一次「被欠薪该怎么办？我月薪 8000，被欠了 2 个月，一共欠多少钱？」：

```
  ✓ 第 1 轮 · 调用 search_knowledge_base(query="被欠薪怎么办 劳动监察 仲裁")
      └─ [1] 第 2 条 · 7. 没钱的时候怎么活 · 证据等级 B（相似度 0.712）
         被欠薪先投诉劳动监察，再申请劳动仲裁，两条路都不收费……

  ✓ 第 2 轮 · 调用 calculator(expression="8000*2")
      └─ 8000*2 = 16000

  ✅ 第 3 轮：模型给出最终答案
```

注意第 1 轮和第 2 轮是**两个不同的工具**，而且第二次调用是模型看到第一次的结果之后才决定的。
这就是 Agent 和「一次 API 调用」的本质差别。

## 二、五分钟跑起来

### 1. 配密钥（唯一需要你动手的地方）

打开 `.env`，填 `LLM_API_KEY`。用 DeepSeek，便宜且支持 function calling：
https://platform.deepseek.com/api_keys

> 这个项目已经复用了 `rag-pdf` 项目的同一个 DeepSeek 密钥，正常情况下不用再填。

### 2. 问一句试试

```bash
cd tool-agent
.venv\Scripts\python.exe run.py "现在几点？顺便算一下 12000*3"
```

或者直接**双击 `start.bat`** 进交互模式，连着问。

### 3. 打开网页版看决策过程（推荐）

```bash
.venv\Scripts\python.exe -m streamlit run app.py
```

网页版会把每一步决策摊开：调了什么工具、什么参数、返回了什么。
**录演示视频用这个**，比命令行直观得多。

## 四、核心：这个循环只有 5 行

`agent.py` 的全部精华就在这几步（简化版）：

```python
messages = [系统提示词, 用户问题]

for 轮 in range(最多步数):
    resp = 模型(messages, tools=工具清单)      # ← 把工具清单交给模型

    if not resp.tool_calls:                    # 它说"不用工具了"
        return resp.content                    # → 这就是最终答案

    for call in resp.tool_calls:               # 它决定要调工具
        result = 执行(call.工具名, call.参数)
        messages.append(工具结果)               # ← 结果塞回对话历史
    # 回到循环开头，模型看着新结果再决定下一步
```

**关键认知**：所谓「Agent 自主决策」，本质上就是**把工具清单和上一步的结果一起喂回去，
让模型重新选一次**。没有魔法，就是多轮循环 + 工具描述写清楚。

## 五、四个工具

| 工具 | 干什么 | 为什么要它 |
|---|---|---|
| `calculator` | 算数学表达式 | 大模型心算大数会错，这是最实在的一个工具 |
| `get_current_time` | 当前日期时间 | 模型不知道"今天"是几号，它的知识有截止日期 |
| `search_knowledge_base` | 检索本地私有知识库 | **接的是隔壁 `rag-pdf` 项目**，让 Agent 能翻你自己的资料 |
| `read_text_file` | 读本地文本文件 | 让它能看你指定的文件、源码、日志 |

第三个是关键：**Agent 的真实价值在于接上你自己的数据**，不然它只是个会算数的聊天机器人。

## 六、护栏（Agent 必配，不配会出事）

Agent 能自己循环，就意味着它也能**自己循环到死**、或者**烧光你的额度**。三道护栏：

| 护栏 | 做法 | 不做的后果 |
|---|---|---|
| **步数上限** | `MAX_STEPS = 8`，用完强制要求它收尾 | 模型陷入死循环，一直调工具 |
| **重复调用拦截** | 同一工具 + 同一参数连续重复 → 插入提示要求直接作答 | 一个参数写错的工具被反复调用 |
| **错误当信息回传** | 工具报错**不抛异常**，把错误文本交给模型 | 一次工具失败整个 Agent 崩掉 |

第三条最容易被忽略，也最能体现水平：
`call_tool()` 里工具出任何问题都返回一句人话（`"参数不合法：xxx"`），
模型看到就能自己改参数重试，或者换一条路。**这才是 Agent 该有的鲁棒性。**

## 七、怎么验证它"选对了工具"

`test_agent.py` 里固定了 12 个问题 + 每题期望的工具，跑一次出一张表：

```bash
.venv\Scripts\python.exe test_agent.py
```

测试集覆盖了三种情况：

1. **单工具**：「现在几点？」→ 只该调 `get_current_time`
2. **多步任务**：「被欠薪该怎么办？月薪 8000 欠 2 个月一共多少钱？」
   → 必须**同时**调 `search_knowledge_base` 和 `calculator`（考它会不会偷懒只调一个）
3. **该克制的时候克制**：「你好，介绍一下你自己」→ **不该调任何工具**

实测结果见下方「实测数据」一节。

## 八、实测数据

`test_agent.py` 的实测结果（模型 `deepseek-chat`，2026-10-10 本机运行）：

| 指标 | 结果 | 含义 |
|---|---|---|
| 工具选择准确率 | **12 / 12 = 100%** | 该不该调、调得对不对 |
| 工具执行成功率 | **12 / 12 = 100%** | 调了之后真的跑成功了吗 |
| 平均调用次数 | 1.25 次 / 题 | |
| 平均完成轮数 | 1.92 轮 / 题 | |

分类看：

- 单工具题（4 题）：全部选中正确工具
- 多步题（4 题）：**全部同时调用了两个工具**，没有偷懒合并
- 克制题（1 题）：「介绍一下你自己」→ 正确地**没有调用任何工具**
- 文件读取题（2 题）：路径里的中文和反斜杠都正常解析
- 知识库题（3 题）：检索命中相关条款

> **别把这个 100% 当成能力证明：** 只有 12 题，而且题是我自己出的，
> 样本小、偏简单。它真正的价值是**回归测试**——
> 以后我改系统提示词、加工具、换模型，跑一遍就知道有没有把原来对的能力改坏。
> 想让它更有说服力，就往 `CASES` 里加更难、更刁的题。

### 一个必须记下来的教训：只测「选对了工具」是不够的

这个测试集的第一版**只检查工具名对不对**，跑出来 12/12 全绿。
后来才发现**知识库工具因为环境里缺 numpy，一直在静默失败**——
它每次都老老实实返回「知识库不可用」，而测试只看到「它调用了 search_knowledge_base」，判定正确。

> **工具挂了，工具选择依然可以是 100%。**

所以现在两个指标分开统计：选择归选择，执行归执行，任一不过都算问题。
`exec_ok()` 会去工具返回的文本里找「不可用 / 出错 / 失败 / 不存在」这类痕迹。

**这条经验比 100% 那个数字值钱**：测试的盲区，往往正好是你没想过要测的那一维。
